# パスマッピングと接続状態の分離

[English](path-state-isolation-design.md)

## スコープと正本

この設計は、Issue #152 で追跡する承認済み Codex App Server 更新計画の Phase 3 と ADR-013 を実装します。Issue #151 の安全な接続ライフサイクルを維持します。エンドポイント検証、トークン読み取り、TLS、診断、再試行、ソケット所有権の正本は、リモート接続の詳細設計です。

App Server との通信はローカル Worker が所有します。既定はローカル stdio です。リモートプロファイルは既存のローカル作業ツリーを既存のサーバー作業ツリーに対応付け、同期は外部で行います。リモートのサンドボックスはサーバーが強制します。ローカルファイルシステム検証が保護するのは Visual Studio ホストのみです。

## パスのドメイン

`LocalPath` と `ServerPath` は別の値です。相互変換は共通の `RemotePathMapper` だけが行います。Worker はプロトコル境界でサーバー値を文字列化し、ローカルファイル操作はマッピングとローカル包含検証に成功したローカル値だけを使用します。

| 項目 | 規則 |
|---|---|
| 絶対ルート | Windows ドライブ、UNC 共有、POSIX の絶対パスをパス体系を区別して受理します。相対パス、ドライブ相対パス、安全に表現できないデバイス名前空間、制御文字、不正なルートを拒否します。 |
| コンポーネント | 正規化したコンポーネント全体を比較します。部分文字列で比較しません。`C:\repo` は `C:\repo2` を含みません。 |
| Windows | 大文字小文字を区別しない序数比較です。区切りと対応する拡張ドライブ・共有プレフィックスを正規化し、UNC 共有の識別を維持します。代替データストリームと危険なローカルファイル名エイリアスを拒否します。 |
| POSIX | 大文字小文字を区別する序数比較です。文字ケースと Unicode コードポイントを維持し、サーバーが指定していない Unicode 正規形で識別を統合しません。 |
| ドット要素 | 明示したルート境界で `.` と `..` を正規化します。逸脱の試みは別ルートに変換せず拒否します。 |
| ルート一致 | ルート自身を相手のルートに変換します。末尾の区切りはルートの識別を変えません。 |
| サーバーパス | Visual Studio ホストの OS と独立して、設定したサーバーのパス体系を使用します。 |
| ローカルファイルシステム | 信頼境界でシンボリックリンクとジャンクションを解決します。解決済みローカルルート内に収まる必要があり、読み取れないリンク、循環、逸脱は拒否します。 |

作業ディレクトリ、アクティブ文書、選択範囲の元ファイル、参照ファイル、添付、`localImage`、変更ファイルパス、ファイル成果物、ローカル open/reveal は同じマッパーを使用します。既存のファイル操作はマッピング済みローカルパスを受け取ります。将来の型付き成果物表示も同じ境界を利用し、App Server の文字列を直接開きません。

Issue #152 はマッパー、物理境界、所有者スタンプを提供し、現在存在するすべての利用箇所に適用します。まだ存在しない利用箇所は後続フェーズが提供し、同じサービスを使用しなければなりません。

| 利用箇所 | 提供 | 必須の境界 |
|---|---|---|
| 作業ディレクトリ、IDE コンテキスト、添付、`localImage`、承認パス、スレッド一覧の作業ディレクトリ | Issue #152 | `RemotePathMapper` + `LocalPathBoundary` |
| 変更ファイルリンク、型付きファイル成果物、画像プレビュー、ローカル open/reveal | Issue #155 | 操作を有効にする前のサーバー→ローカルマッピングと物理的包含 |
| 保存済み添付、復元履歴、保持した下書き | Issue #153（表示と操作は Issue #155） | 所有者パーティションと世代、ファイル操作前のサーバー→ローカルマッピング |

スレッド一覧はサーバーの作業ディレクトリをマッピング済みローカルパスとしてのみ表示します。マッピングできない場合はサーバー文字列ではなく、固定のリモートディレクトリ表示を使います。

`turn/start` 前に、明示的なすべての添付と物理的な包含を検証します。マッピングできない、存在しない、読み取れない、または保護された添付がある場合、または異なる添付が 10 件を超える場合は、ファイル名だけを示す上限のある対処可能な理由で開始要求全体を拒否します。添付を一部だけ送信せず、機密性のある絶対パスをエラーに表示しません。任意の IDE コンテキストは安全にマッピングできる場合だけ含めます。ローカルファイルを開く・表示する時にも物理的包含を再検証します。

スキルパスは、上限を設けたサーバー提供の識別子です。完全一致の `(Name, Scope, Path)` の一部として比較し、そのまま送信します。リモートスキルは Visual Studio ホストでのファイル存在確認に依存しません。

## 所有者の識別とライフサイクル

Worker は取得した接続所有者に対して不透明な状態パーティションを割り当てます。入力は接続種別、プロファイルとエンドポイントのメタデータ、ローカル・サーバー作業ルート、認証資格情報の所有者、アカウントの識別を区別します。フィールドは曖昧さなく、上限を設けてハッシュ化します。トークン内容とアカウント詳細は Remote UI や診断に渡しません。

bearer トークンのダイジェストは、ローテーションを含めた明示的ハンドシェイクを区別します。Worker 内部の区別にのみ使い、上流の認証主体を識別できたとは見なしません。CLI 0.159.1 の account 契約には普遍的な正本アカウント ID がありません。API キーのアカウントは種別のみ、ChatGPT アカウントは nullable なメールとプランのメタデータです。メールとプランだけでアカウント間の共有を許可できません。安定した所有者識別が得られない場合は Worker・接続試行ごとの揮発パーティションを使い、スキルスナップショットのディスク読み取り・書き込みの両方を無効にします。このため、固定契約ではローカル・リモートとも Worker 間の永続キャッシュ共有を有効にしません。

アカウント変更とログアウトは、旧所有者の保留処理と状態を無効化します。一方的なアカウント通知はアカウントを再読み込みして検証し、アカウントの識別が変わった場合だけ境界とします。リモート所有者の変更では、新所有者の動作を受理する前に旧ソケットを無効化します。ソケットの無効化は外部サーバーを停止せず、変更操作を再送しません。

### アカウント変更のライフサイクル

| 契機 | 所有者の扱い | 結果の接続 |
|---|---|---|
| この所有者が要求したログアウト | `account/logout` 成功後に旧所有者を無効化します。 | Worker は同じ設定で新しい揮発所有者に直ちに接続します（ローカル: 新しい子プロセス、リモート: トークンファイルを再読込して新しいソケット）。アカウントはサインアウト表示になり、Sign in を使用できます。 |
| この所有者が開始したサインインと `loginId` が一致する `account/login/completed` | `success` の値にかかわらず旧所有者を無効化します。 | 同じく新所有者へ自動接続します。アカウントは新所有者が読み取ります。 |
| `account/updated`、または `loginId` が一致しない `account/login/completed` | 同じ所有者でアカウントを再読み込みし、アカウント指紋を比較します。所有者の最初のアカウント読み取りが完了する前に届いた通知は、その読み取りで扱います。 | 指紋が同じ: アカウント状態を更新し、所有者は維持します。指紋が異なる: 旧所有者を無効化し、Degraded として利用者が明示的に再接続・再起動します。 |

アカウント指紋は、`account/read` のアカウント種別、メール、プランから作る Worker 内部だけの SHA-256 ダイジェストです。Remote UI、診断、ディスクには渡しません。所有者の最初のアカウント読み取りで記録し、以降の読み取りで異なる指紋が返った場合に所有者を無効化します。CLI 0.159.1 はアカウントが変わらなくても起動直後に `account/updated` を送るため、すべての通知を境界にすると新しい接続がすべて無効化されます。所有者自身の `account/logout` の処理中に扱うアカウント通知や識別変化は、応答と通知の処理順にかかわらず、そのログアウトとして扱います。

自動接続は遷移ゲート内で `initialize`/`initialized` と既存の接続手順だけを実行します。メッセージ、承認、その他の変更操作は再送せず、通常の所有者置換と同じく選択状態を消去します。失敗した場合は通常の Degraded を発行します。新しいセッションの開始中は接続状態にアカウント変更を表示し、会話表示にはエラーを追加しません。

各操作は現在の所有者と世代を取得します。結果の確定、コールバックの発行、表示状態の適用前に両方を検証します。旧応答、通知、切断コールバック、承認回答、モデル読み取り、カタログ更新は新所有者の状態を変更できません。無効化で保留要求・応答と承認・監査表示を消去し、古い更新が新パーティションに保存されることを防ぎます。アカウント所有状態を読み書きするすべてのWorker要求（モデル、スレッド、スキル、MCP、権限プロファイル、レート制限の読み取りを含む）は、取得した所有者を保持します。Workerは遷移ゲート内で検証し、app-serverの応答を待つ前にゲートを解放するため、承認・ユーザー入力の回答、所有者の無効化、ウォッチドッグが保留中の呼び出しの後ろで待たされることはありません。

## 状態の境界

| 状態 | 所有者とリセット |
|---|---|
| ソケット、保留 RPC、サーバー要求 | Worker の接続世代と取得した所有者に所属し、置換前に無効化します。 |
| スキル | Worker のメモリと永続ストアは所有者パーティションと作業ルートで区別します。ターン前の force reload による識別検証を維持します。 |
| モデルカタログと未対応メソッド | Worker/UI の結果を所有者に結び付け、置換で旧カタログと機能状態を無効化します。 |
| 使用量 | 所有者スナップショットを消去し、置換後の遅い読み取り・push を Worker の発行フィルターと Extension の両方で拒否します。 |
| 承認許可と監査 | 許可は所有者・接続寿命をまたぎません。監査表示にも上限と所有者を設けます。 |
| 選択会話と会話表示・履歴 | エンドポイント、プロファイル、ルート、アカウント、認証主体の置換で決定的に消去します。 |
| 入力、選択スキル、添付、次ターン設定 | 有効な状態は所有者置換で消去します。旧所有者の下書きだけをメモリに隔離し、自動では復元しません。接続先の確認と現在の所有者の会話選択の後、明示的に復元できます。送信は別操作です。 |
| ローカルファイル操作 | マッピング済みローカル値と、現在の設定ルートに対する物理的包含が必要です。 |

下書き、履歴、添付に新しいディスク保存を追加しません。置換時は有効な会話/transcript と live owner state を消去し、明示確認用の分離されたメモリ内下書きだけを保持します。置換 Worker は以前の Worker 内部 fingerprint との継続性を証明できません。現在の target を確認し、その owner の履歴から会話を選んだ後、quarantine 下書きを明示的に復元または破棄できます。復元は本文を composer にコピーするだけで、送信は別操作です。送信時に現在の添付と選択を再検証します。quarantine は承認、cache、credential、以前の thread ID、保留要求を含みません。詳細は[接続・履歴の復旧](connection-history-recovery-design_ja.md)を参照してください。 アカウント通知はアカウントを再読み込みして検証し、アカウントの識別が変わった場合だけ境界とします。リモート所有者の変更では、新所有者の動作を受理する前に旧ソケットを無効化します。ソケットの無効化は外部サーバーを停止せず、変更操作を再送しません。

## 実装と検証

1. 型付きの正規化・マッピングとローカル物理境界検証を実装します。Windows→POSIX、Windows→Windows、POSIX サーバー→Windows ローカル、拡張ドライブ・UNC ルート、デバイスエイリアス、代替データストリーム、末尾ドット・空白、予約名、ルート自身、混在区切り、Unicode、ケース、ドライブ・共有不一致、兄弟プレフィックス、トラバーサル、シンボリックリンク・ジャンクション逸脱を検証します。
2. 既存の送受信パス利用箇所を統合します。拒否添付は `turn/start` を送らず、リモートスキル識別はホストのファイルシステムを参照せず、マッピングできないサーバーパスはローカル操作にならないことを検証します。
3. Worker のキャッシュと許可を分離し、操作を所有者・世代に結び付けます。二つのエンドポイント、プロファイル、アカウント、資格情報所有者、ルート、同時 Worker と、トークンローテーション・旧所有者の遅延イベントを検証します。
4. 所有者置換で Extension の選択状態をリセットし、非同期のモデル、履歴、使用量、スキル、承認、送信、ファイル操作を保護します。明示的 connect/reconnect を維持し、上限のあるマッピングエラーを表示します。
5. 対象回帰と Core/UI 全テスト、警告ゼロの Debug/Release ビルド、固定 CLI 0.159.1 の契約・スキーマ検証、VSIX 内容と埋め込み XAML 検査、`git diff --check` を実行します。Experimental Instance の実表示を確認し、ソース・単体テストの証拠と区別して記録します。

合格には、パスマッピングとすべての状態境界が所有者変更に対して安全に拒否する必要があります。画面の証拠は接続切り替え、選択状態の消去、添付拒否、リモートスキル選択を記録します。実行できない検証は implementation/task の記録で明示的に未完了とします。
