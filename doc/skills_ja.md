# Codex カスタムスキル対応

## 対象範囲

Visual Studio拡張機能は、現在のワークスペースのCodexスキルカタログを提示します。読み取り専用の
`/skills`トランスクリプト一覧、コンポーザー内のインライン`$<name>`メンション候補、スコープと
読み込みエラー詳細を持つスキルパネル、有効/無効切り替えトグルです。実装はGitHub Issue #119と
8件のsub-issue（#120-#127）で管理しています。

`$`は本リリースではスキルメンション専用に予約されています。他のメンション規約とは共有しません
（[doc/adr.md](adr.md)のADR-011を参照）。

## プロトコルメソッド

| メソッド | 用途 |
|---|---|
| `skills/list` | セッションの作業ディレクトリに対するスキルを検出します。常に`cwds: []`で呼び出し、App Serverはこれをセッションの単一作業ディレクトリに解決します。 |
| `skills/config/write` | 1つのスキルを名前またはパス（排他的）で選択し、有効/無効を切り替えます。 |
| `skills/changed` | カタログがディスク上で変化したことを示すサーバー起点通知（空の`params: {}`）。Workerは会話イベントではなくキャッシュ無効化シグナルとして扱います。 |

`skills/list`のレスポンスは、`SkillsListResponse.data`（cwdごとのエントリの配列で、各エントリが
`skills[]`と`errors[]`を持つ）を`ListSkillsResult { Skills, Errors, IsTruncated }`にフラット化
したものです。`cwds: []`呼び出し形式は常にエントリ1件を返すため、この変換は無損失です。
`SkillInfo.Cwd`と`SkillLoadError.Cwd`は将来のmulti-root対応で契約形状を再変更しなくて済むよう、
各要素に個別に保持しています。除外理由の詳細（`interface.brandColor`、アイコンパス、
`interface.defaultPrompt`、`dependencies.tools[]`が意図的にコントラクトから除外されている理由を
含む）はADR-008を参照してください。

どちらのメソッドも`experimentalApi`オプションではゲートしていません。対応状況はApp Serverの
`-32601`（メソッド未検出）応答のみで検出し、本拡張の他の機能と同じ能力プローブ方式に従います
（ADR-008）。

## Workerのキャッシュと無効化

`CodexSessionService`は直近の`skills/list`成功結果をキャッシュし、`forceReload`が指定されない
限り再呼び出しをキャッシュから返します。キャッシュは以下でクリアされます。

- `InitializeAsync`（新しいApp Serverプロセスは全く異なるスキル構成を持ちうるため）
- `skills/changed`通知
- `skills/config/write`の成功

キャッシュをextensionではなくWorkerに置く理由はADR-009を参照してください。

## コンポーザーのメンションとターン入力

`$`に続けて文字を入力するとインライン候補一覧が開きます（既存の`#`ファイルメンションと同様の
オーバーレイ）。候補はキャッシュ済みカタログから構築され、`$$`は`$`のエスケープです。候補を選択
するか完全な`$<name>`を入力してターンを送信すると、トークンをキャッシュ済みカタログに照合し、
一致すればファイル添付とは別枠の`{ type: "skill", name, path }`ターン入力アイテムを追加します
（ADR-010）。未解決のトークンはエラーにせず、そのままの文字列として残します。

解決処理と候補表示はいずれも、切り詰められたカタログ（workerの`MaxSkills`/`MaxSkillErrors`表示上限
に達した状態）に対しては動作を拒否します。scope衝突の誤った解決や、表示範囲外エントリの候補提示は
送信時に実害があるためです。ターン入力アイテムは1ターンあたり最大5件かつパスで重複排除します。
スコープをまたぐ名前衝突は決定論的に解決します（有効なスキルが無効なものより優先、その後
`repo` > `user` > `system` > `admin`、最後にパスの序数比較）。

スキルパスは、ファイル添付・メンションを管理するpath-access policyを通しません。これらのパスは
ユーザーが選択したファイルではなく、App Server自身の`skills/list`応答由来だからです。
`scope: user`のパスはディレクトリ（`File.Exists`チェックに失敗する）であり、
`scope: system`/`admin`のパスは日常的にワークスペース外に存在します。信頼境界の詳細な論拠は
ADR-010を参照してください。

## スキルパネル

ツールバーのトグルでスキルパネルを開きます（履歴・使用状況フライアウトとは相互排他）。各スキルの
表示名、スコープ、簡潔な説明、有効状態に加え、カタログと共に報告されたスキルごとの読み込みエラー
を一覧表示します。本パネルはpermission profileピッカーより意図的に寛容です。不完全な一覧から選ぶ
ことはpermission profileにとってセキュリティ上の判断ですが、スキルパネルは純粋に情報提供目的
のため、切り詰められたカタログも（注記付きで）そのまま表示します（ADR-012）。無効なスキルは
非表示にせず「(disabled)」サフィックス付きで表示し続けます。

スキルのエントリと読み込みエラーは、Remote UIのコレクションに対してその場でマージします
（`Insert`/`Move`、`Clear`+`Add`は使いません）。これにより毎回の更新でパネルの一覧状態が
一瞬無効化されることを避けています。

## 有効化・無効化

各スキル行にはトグルボタンがあり、`scope: system`/`admin`のスキル（組織ポリシーで管理）に対しては
完全に非活性化されます。クリックすると確認ダイアログなしに`skills/config/write`を呼び出します。
`/feedback`とは異なり、これはローカルで即座に可逆な項目単位の設定であり、外部へのアップロードを
伴わないためです（ADR-013）。UIは楽観的な状態更新を一切行いません。行の有効状態はサーバーの
`effectiveEnabled`応答からのみ設定され、組織ポリシーが要求を上書きした場合は要求値と異なることが
あります。

## 検証

Coreテストは、カタログのフラット化、切り詰め、スキル・エラーテキストのシークレット秘匿、
キャッシュのヒット/無効化、能力プローブのフォールバック、`skills/config/write`のセレクタ検証
（名前XORパス）、`effectiveEnabled`のパススルーをカバーしています。

UIテストは、`/skills`トランスクリプト一覧、メンションの解析・解決（切り詰められたカタログの
ガードやターン入力の上限・重複排除を含む）、コンポーザー候補オーバーレイの挙動（開く・移動・
確定・`skills/changed`での終了）、パネルの履歴/使用状況との相互排他、その場マージ、トグルの
`effectiveEnabled`への整合をカバーしています。
