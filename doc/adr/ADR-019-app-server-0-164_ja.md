# ADR-019: Codex App Server 0.164.0 対応、バージョン段階、共通プリセット

[English](ADR-019-app-server-0-164.md)

- 日付: 2026-10-25
- 状態: 承認済み
- 追跡: [Issue #226](https://github.com/kkamegawa/vsextensionforcodex/issues/226) と子 Issue [#227](https://github.com/kkamegawa/vsextensionforcodex/issues/227), [#228](https://github.com/kkamegawa/vsextensionforcodex/issues/228), [#229](https://github.com/kkamegawa/vsextensionforcodex/issues/229), [#230](https://github.com/kkamegawa/vsextensionforcodex/issues/230), [#231](https://github.com/kkamegawa/vsextensionforcodex/issues/231)

## 背景

Codex CLI 0.164.0 では、拡張に関係する次の変更が入りました。

- `/model` と `/permissions` で引数を直接指定できるようになりました。
- `tui.presets` に 10 個のプリセットスロットが追加されました。
- 生成画像が attachment-store の参照（`fileId`）として保存されるようになりました。
- MCP のツール一覧にメタデータが付くようになりました。
- サーバー側に診断 ZIP を書き出す `feedback/save` が追加されました。
- サーバー側の修正として、再開時に全体の既定値ではなく保存済みのスレッド設定を復元するようになりました。また、compaction に失敗しても部分的な要約が残らなくなりました。

リモートサーバーは 0.161.0〜0.163.0 のまま動いている場合があります。これらのバージョンは再開時に全体の既定値を返し、`feedback/save` も `fileId` も持っていません。

## 決定

- **対応バージョン**: 最低対応を 0.161.0、契約基準を 0.164.0、回帰対象を 0.163.0／0.162.1／0.161.0 とします。これより古いサーバーと、バージョンを判定できないサーバーへの接続は拒否します。詳細は同日付の ADR-011 改定に記録しています。
- **機能段階**: 接続ごとに次の機能段階を Worker が算出し、Extension に渡します。
  - 基本: 0.161.0 以上
  - 0.163: 0.163.0 以上
  - 0.164: 0.164.0 以上

  プリセット、再開時のスレッド設定の反映、生成画像の新しい表示処理、MCP 状態の分離表示、診断 ZIP の保存は、0.164 段階でのみ有効にします。それより古い接続では既存の挙動を維持します。フィールドの欠落や未知の列挙値を許容する処理は、すべての段階に適用します。
- **`/model` の引数**: CLI 0.164.0 のスラッシュコマンド解析と同じ規則で解析し、すべて検証してから適用します。
  - 速度を省略した場合、変更後のモデルが現在の tier に対応していればその tier を維持します。CLI は省略時に tier を送らないため、これは意図的な差異です。
  - `standard` は、要求値 `default` として送ります。
- **プリセット**: 接続先サーバーの `tui.presets` を CLI と共有します。
  - 読み取りには、作業ディレクトリ（`cwd`）を指定した `config/read` のレイヤー情報を使います。
  - 書き込みは `tui.presets.<digit>` に対する 1 件の `config/batchWrite` とし、`expectedVersion` で競合を検出します。
  - ユーザー以外のレイヤーが優先するスロットは編集できません。ユーザー以外のレイヤーでも定義されているスロットは削除できません。
  - プリセットを呼び出すと入力欄に展開するだけで、送信はしません。CLI はキューに入れて実行するため、これは意図的な差異です。
- **再開時の設定**: 0.164 段階で再開した際、`serviceTier` が null であれば通常速度とみなし、それまでの tier を解除します。
- **`fileId`**: 公開 RPC で attachment-store を解決する手段がないため、解決できない参照として扱います。
- **診断 ZIP**: ユーザーが明示的に操作したときだけ保存します。
  - ログの同梱は既定でオフにします。
  - 既に存在するパスへの保存は拒否します。
  - 切断やタイムアウトは「結果を確認できなかった」として扱い、自動で再送しません。
- **compaction**: すべての段階で、表示する履歴はサーバーから取得したものとします。compaction が完了したとみなすのは、`thread/compacted` を受け取ったとき、または `contextCompaction` 項目が完了したときだけです。旧段階で上流に残る制約は、クライアント側で回避せず、制約として文書に記載します。
- **Worker 契約**: v26 に更新します。

## 結果

- 0.159.1 やソースビルド（`0.0.0`）を使っている利用者は、CLI を更新するまで接続できなくなります。
- 0.161.0〜0.163.0 の利用者は接続できますが、0.164 の機能は使えません。非表示になった機能については、必要なバージョンを UI で案内します。
- 実行中の CLI はバージョンを検査せずに書き込むため、CLI でプリセットを編集しても、拡張が次に読み取るまでその変更を検出できません。
- 承認済みの設計と計画は [app-server-0-164-design_ja.md](../app-server-0-164-design_ja.md) と [app-server-0-164-plan_ja.md](../app-server-0-164-plan_ja.md) にあります。
- [ADR-020](ADR-020-app-server-0-166_ja.md) は検証対象を 0.166.0 に上げ、0.165 と 0.166 の階層を追加します。各階層は自身の導入版と比較するため、0.164 階層は検証対象ではなく 0.164.0 で定義されます。
