# ADR-021: 制約のある環境と experimental 機能の検証方針

[English](ADR-021-validation-policy.md)

- 日付: 2026-11-04
- 状態: 採用
- 関連: [ADR-020](ADR-020-app-server-0-166_ja.md)

## 背景

プロジェクトでは、SSO が有効な組織などのエンタープライズ環境や、実際の切り替えに必要な複数のワークスペースを利用できません。experimental 機能は変更される可能性があり、安定した機能より検証の優先度を低くします。

## 決定

- エンタープライズ環境を利用できない場合、SSO を含む同環境でのテストは必須とせず、未検証として記録します。
- 複数のワークスペースが利用できない間、ワークスペース切り替えはテストせず、実際の切り替えを未検証として記録します。
- experimental 機能は必要に応じて実装し、テストは最小限とします。実施した確認を記録し、網羅的に検証したとは表現しません。
- 0.166 設計書に記載した細かな実行状態の組み合わせについて、追加の個別手動受け入れテストを必須にしません。対象は reasoning effort の変更、resume / fork 後の承認設定、Stop / Plan 変更時の保留操作、安全ブロックです。これらは機能上の期待として維持し、直接の証拠がない組み合わせは「受け入れ済み・未テスト」と記録します。Issue が報告された場合、またはメンテナーが問題に遭遇した場合に再現・検証します。約60秒のアイドル後に届く `thread/closed` と同一 thread の再開は段階1ですでに確認し、[Issue #241](https://github.com/kkamegawa/vsextensionforcodex/issues/241) に記録済みです。段階4のためだけに再テストしません。
- Visual Studio Experimental Instance は拡張機能をテストするための実行環境であり、Codex の experimental 機能とは別です。
- 0.166 の作業では、メンテナーの判断によりシンボリックリンクのテストケースをリリース検証の対象外とします。スキップはスキップとして記録します。

この方針は、上記の決定と矛盾する検証要件に限り ADR-020 および 0.166 の設計・計画に優先します。機能要件やセキュリティ要件は変更しません。

## 代替案と影響

エンタープライズ、ワークスペース、experimental 機能の完全な検証を必須にすれば対象範囲は広がりますが、利用可能な環境とリソースでは完了できません。本方針では、それらの動作の検証が限定的なまま提供できます。Fake や自動テストだけでは実環境での動作は確認できないため、未テストのシナリオと実際の検証結果を分けて記録します。上記の細かな実行状態の組み合わせは、事前の再現を必須にせず、Issue が報告された場合またはメンテナーが問題に遭遇した場合に調査します。

## 決定の履歴

- 2026-11-04: この会話におけるメンテナーの検証方針を採用しました。従来の 0.166 の受け入れ条件はより広い検証を要求していましたが、利用できる環境がないことと experimental 機能のテストを限定する判断により変更しました。
- 2026-11-06: 列挙した細かな実行状態の組み合わせは専用の手動テストなしで受け入れました。60秒アイドル後の close / resume の既存証拠は維持し、他の項目は問題が報告・発生した場合に検証します。
