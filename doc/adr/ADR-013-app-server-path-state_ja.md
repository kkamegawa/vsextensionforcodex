# ADR-013: App Server のパスと状態の分離

- 日付: 2026-09-13
- 状態: Accepted
- 追跡: Issue #152

## 決定

- ローカルとサーバーのパスを別の型で表現し、ルートをコンポーネント単位でマッピングします。
- 作業ディレクトリ、IDE コンテキスト、添付、画像、変更リンクに共通のマッピングサービスを適用し、マッピングできない添付は送信前に拒否します。
- 接続、WebSocket、スキル、モデルカタログ、使用量、承認、選択会話、添付、履歴を、接続、アカウント、認証主体、作業ルートごとに分離します。
- 有効な接続世代と送信結果を取得した認証主体に結び付けます。アカウント切り替え、ログアウト、認証所有者変更は、新主体の有効化前に旧所有者のリモートセッション、保留要求、WebSocket、モデル、キャッシュ、遅延イベントを無効化します。
- リモートのサンドボックスはサーバー所有とし、ローカル保護ディレクトリ検証を代用しません。

## 結果

パス変換を監査可能にし、リモートセッションや認証所有者が別主体のキャッシュ・状態を混在させることを防ぎます。

## 所有者識別とキャッシュパーティションの契約

- 日付: 2026-10-03
- タスク: Issue #152
- 正本: 承認済み Phase 3 の分離要件は、ADR-010 の workspace のみのキャッシュキーに優先します。
- ローカル・サーバーのパスドメインを分け、共通コンポーネントマッパーと物理的なローカルルート包含検証を使います。Windows ドライブ・UNC と POSIX はホスト OS から独立して比較規則を決定し、Unicode コードポイントを維持します。
- すべての状態と結果の公開を、不透明な所有者パーティションと接続世代に結び付けます。アカウント・認証変更で、新所有者の受理前に旧リモートソケットと保留処理を無効化します。
- CLI 0.159.1 は普遍的な正本アカウント識別を提供しません。nullable なメール、プラン、共通 bearer ダイジェストは、インスタンス間やオフラインのアカウント変更をまたぐ所有者継続を確立できません。安定した所有者を確認できない場合は Worker・試行ごとの揮発パーティションを使い、共有永続スキルスナップショットを読み書きしません。
- 将来、契約に基づく安定パーティションが利用できる場合にも、既存永続キャッシュの上限と atomic・プロセス間書き込み規則を維持します。旧 workspace のみのスナップショットで所有者共有を許可しません。
- 所有者置換で、選択会話、下書き、添付、モデル、使用量、スキル、承認許可・監査、履歴を消去します。旧所有者で取得した非同期結果を破棄します。
- リモートスキルパスは不透明なサーバー識別子とし、リモートのサンドボックス強制はサーバーの責任とします。

詳細契約: [パスマッピングと接続状態の分離](../path-state-isolation-design_ja.md)。

## アカウント変更時の再接続と利用箇所の範囲

- 日付: 2026-10-04
- タスク: Issue #152 フォローアップ
- 所有者が要求したログアウト、または所有者が開始したサインインと `loginId` が一致する `account/login/completed` は、旧所有者を無効化した後、同じ設定で新しい揮発所有者へ自動接続します。既存の接続手順だけを実行し、変更操作を再送しません。一方的な `account/updated` と一致しないサインイン完了は従来どおり Degraded とし、明示的な再接続を必要とします。理由: 承認済み計画は旧主体の無効化後に新主体を有効化します。すべてのサインインで Degraded に留まると、ログアウト後にサインインできませんでした。
- マッピングできない、存在しない、読み取れない、または保護された明示的添付は `turn/start` 全体を拒否し、添付を一部だけ送信しません。
- 変更ファイルリンク、型付きファイル成果物、画像プレビュー、open/reveal は Issue #155、保存済み添付、復元履歴、保持した下書きは Issue #153 が提供します。どちらもここで提供するマッパー、物理境界、所有者パーティションを使用します。
- リモートモードは Issue #153 が完了し、上流の WebSocket 転送が実験的でなくなるまで Preview を維持します。
