# ADR-015: 質問・承認・MCP 対話

[English](ADR-015-app-server-interaction.md)

- 日付: 2026-10-05
- 状態: 承認済み
- 追跡: [Issue #154](https://github.com/kkamegawa/vsextensionforcodex/issues/154)

## 背景

2026-09-13 に承認された決定は Worker 契約 v15 を前提とし、拡張機能で秘密入力専用の安全な経路と、ローカルのネイティブ本人確認経路を完全に実装できるとしていました。実装済みの契約 v19 と固定版 Codex CLI 0.159.1 を確認したところ、この成功経路の前提を満たせない制約が分かりました。上流の本人確認 provider は macOS のみをサポートし、この拡張 client は上流の適格対象に含まれません。現行拡張には秘密入力を分離する経路もありません。Gateway OAuth では、認証を必要とする RPC より前にローカル stdio の起動ゲートを実行する必要があります。リモート peer はその OAuth 変更フローを所有しません。

## 決定

- Worker 契約 v19 から開始し、merge 時点で次に利用可能な契約 version を割り当てます（途中変更がなければ v20）。固定した CLI／SDK／runtime の基準は変更しません。
- 質問、権限要求、コマンド承認、MCP elicitation、Gateway OAuth、未対応の本人確認要求を、個別の型付き対話として扱います。接続世代と request ID に結び付く共通保留 registry を使い、回答を検証してから完了権を原子的に取得します。キャンセル、timeout、切断、resolved、旧世代の競合があっても応答は最大1回です。
- 質問は独立したカードで表示します。既定値と選択状態は表示情報であり、明示的な Submit を回答とします。secret マーカー付き入力は UI に投影する前に検出して、理由を示して拒否します。秘密値を通常 UI、会話、ログ、設定、診断、例外へ出しません。
- 要求された権限の部分集合だけを返します。既定 scope は turn とし、session scope は明示選択を必要とします。ルール変更を伴うものを含め、コマンド承認のすべての選択肢を保ち、破壊的操作には既存の承認ポリシーを適用します。
- 仕様化された MCP form field を UI と Worker の両方で検証します。未対応の拡張 schema は、その capability を宣言せず理由を示して拒否します。検証済み認証 URL は明示的なユーザー操作の後にだけ開きます。OAuth の期限切れ／失効や `reauthenticationRequired` は再認証状態として扱い、古い elicitation を終了し、新たな明示的ツール呼び出しを要求します。UI のキャンセルはサーバー側キャンセルを意味しません。失敗したツール呼び出しを自動再送しません。
- ローカル stdio に限り `explicitGatewayOauth` を宣言し、各接続で初期化後、認証を要する RPC より前に `account/gatewayOAuth/read` が成功することを要求します。login／cancel／changed 通知と明示的なブラウザー起動に対応し、他の RPC 処理を塞ぎません。未対応または起動時 read 失敗の場合は認証付き RPC を停止し、自動ブラウザー認証へ移りません。Remote は状態と案内だけを示し、login／cancel の変更操作を行いません。
- 上流が Windows とこの拡張 client をサポートするまで、ネイティブ本人確認の成功経路を延期します。今回 capability を宣言・転送せず、要求を理由付きで拒否します。challenge、proof、credential を外部に露出しません。
- 添付の復旧は Issue #153、添付の操作と表示は Issue #155 が担当します。Phase 5 は添付の契約や UI 動作を追加しません。

## 影響

対話の所有者、応答、キャンセルの意味が明確になります。未対応の秘密入力と本人確認は、秘密内容を露出する前に理由付きで失敗します。ローカル Gateway OAuth は read ゲートの成功前に開始できず、Remote はこの capability に対して読み取り専用です。再認証後は新しいツール呼び出しを要求し、配送結果が不確かな変更操作を自動再送しません。

## 決定履歴

- 2026-09-13: 以前の ADR は v15 に基づき、ネイティブ本人確認の成功経路と保護された秘密入力を前提に承認されました。この承認は履歴上のものであり、今回の前提変更を承認したことにはなりません。
- 2026-10-05: Issue #154 の仕様全体を確認した保守担当者の承認を受けました。この決定は 2026-09-13 の前提を置き換えます。
