# Codex App Server 0.163.0 実装記録

追跡 Issue: #217–#223。承認済みの[設計](app-server-0-163-design_ja.md)と[計画](app-server-0-163-plan_ja.md)。英語記録: [English](implementation-app-server-0-163.md)。

## 実装内容

- 契約マニフェストを schema version 2 に更新し、対象を 0.163.0、独立した回帰基準を 0.162.1 と 0.159.1 にしました。版ごとのリリースハッシュ、stable／experimental のメソッド表、既知差分を管理し、生成スキーマも版別に保持します。
- Fake App Server の既定版を 0.163.0 にし、0.162.1 回帰シナリオを追加、Worker 契約を v25 に更新しました。
- stdio と WebSocket の応答で JSON-RPC error.data を上限付きで保持します。競合として扱うのは -32600 かつ reason が readStateConflict の場合だけです。埋め込み状態は通常の検証を通し、欠落または不正なら thread/read で再取得します。
- 実験的API専用の既読状態、5種類の状態、世代付き通知、明示的な既読／未読操作、不透明なrevision、会話単位の更新直列化、thread/read による競合後の再取得、owner・選択世代の保護を追加しました。会話を開く・表示するだけでは既読にしません。
- 履歴の全件再取得とページ追加にowner・要求の検証、重複排除、失敗時の既存一覧保持、カーソル維持を追加しました。存在しない会話に関する作業の取消は、同じownerの完全な一覧が成功した場合だけ行います。
- legacy Windows sandbox許可リストをMXC可否の判定に使う誤りを修正しました。ローカルでのMXC使用禁止、initialized 前のバージョン判定、省略可能な windows.allow_mxc 診断、サニタイズ済み起動エラー説明を追加しました。
- セットアップガイドなどを英語・日本語で更新しました。MCP elicitation は既存の serverRequest/resolved 経路をFakeで検証しました。実機 App Server での通知到達性はこの環境では検証していません。コア側の破棄イベントがクライアントへ届くとは保証せず、既存の5分タイムアウトと切断時の回収をフォールバックとして維持しています。

Coreの5件とUIの1件はスキップとして記録し、成功件数には含めていません。統合 verify-release.ps1 -Configuration Both は起動しましたが、このセッションで進捗を確認できず停止しました。スキーマ、ビルド、テスト、VSIXの各検証は上表のとおり個別に実行しました。
