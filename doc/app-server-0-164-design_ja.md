# Codex App Server 0.164.0 対応設計

[English](app-server-0-164-design.md)

追跡: [Issue #226](https://github.com/kkamegawa/vsextensionforcodex/issues/226) と子 Issue [#227](https://github.com/kkamegawa/vsextensionforcodex/issues/227), [#228](https://github.com/kkamegawa/vsextensionforcodex/issues/228), [#229](https://github.com/kkamegawa/vsextensionforcodex/issues/229), [#230](https://github.com/kkamegawa/vsextensionforcodex/issues/230), [#231](https://github.com/kkamegawa/vsextensionforcodex/issues/231)。2026-10-25 承認。

## 目的

Visual Studio 拡張機能を Codex App Server 0.164.0 の契約に合わせて更新する。追加・定義する内容は次のとおり。

- `/model` の引数指定
- CLI と共有するプリセット
- 再開時のスレッド設定の反映
- 生成画像の参照
- MCP 状態の分離表示
- 診断 ZIP の保存
- compaction 失敗時と圧縮済み履歴の扱い

あわせて、最低対応 CLI を 0.161.0 に引き上げ、それより古いサーバーへの接続を拒否する。

判断の記録は [ADR-019](adr/ADR-019-app-server-0-164_ja.md) と、同日付の ADR-011 改定にある。

## 1. 対応バージョンと契約

### バージョン方針

| 役割 | バージョン |
| --- | --- |
| 最低対応（ローカル・リモート共通） | 0.161.0 |
| 契約基準・推奨 | 0.164.0 |
| 回帰対象 | 0.163.0、0.162.1、0.161.0 |
| 対象外 | 0.161.0 未満（0.159.1 を含む） |

0.159.1 は、契約マニフェスト、CLI 導入補助、Fake App Server の回帰 surface、CI、セットアップ文書から外す。0.159.1 のためだけにある次のコードも削除する。

- バージョン判定の `serverInfo.version` フォールバック
- MCP OAuth 応答に `loginId` がない場合の、サーバー名による照合
- 0.159.1 がフィールドを無視することを前提にしたコメント

対応するすべてのバージョンは、`initialize` で `userAgent` を、`mcpServer/oauth/login` で `loginId` を返す。

experimental API は明示的な opt-in のままとし、既定では無効にする。

### 契約マニフェスト

`app-server-contract.json` をスキーマバージョン 3 に上げ、必須フィールド `minimumVersion` を追加する。

- `minimumVersion` は `0.161.0`、`targetVersion` は `0.164.0`、`regressionVersions` は `0.163.0`、`0.162.1`、`0.161.0` とする。
- 対象版と回帰版のそれぞれについて、リリースタグ、Windows x64 asset、SHA-256 を固定し、使用する stable／experimental メソッドを列挙する。
- 次のいずれかに当てはまる場合、検証を失敗させる。
  - `minimumVersion` がない
  - `minimumVersion` が固定済みバージョンの最小値でない
  - `minimumVersion` が回帰版に含まれていない
  - `minimumVersion` 未満のバージョンが固定されている
- `knownDifferences` には回帰版ごとに 1 項目を置く。
- 0.164.0 の使用メソッドに `config/batchWrite` と `feedback/save`（どちらも stable）を追加する。

4 バージョン × 2 surface のスキーマを、ハッシュを検証した公式実行ファイルから生成する。対象版は回帰版ごとに個別に比較する。

スクリプト、CLI 導入補助、CI マトリクス、Fake App Server は、バージョンをマニフェストから読み取る。Worker は最低版と対象版を定数として持ち、単体テストでマニフェストとの一致を検証する。

### バージョン判定規則

1. **情報源**: `initialize` 応答の `userAgent` の先頭プロダクト（`<originator>/<version> (<os>; <arch>) ...`）を使う。originator には `Codex Desktop` のように空白を含むことがあるが、`/` は含まない。そのため、最初の `/` から次の空白までをバージョンとする。それ以外のフィールドや `--version` の別プロセスは使わない。
2. **構文**: Semantic Versioning 2.0 に従う。
   - `MAJOR.MINOR.PATCH` は先頭ゼロのない 3 つの数値で、任意の `-prerelease` と `+build` が続く。
   - 長さは 64 文字以内とし、既存の文字種検証を適用する。
3. **比較**: Semantic Versioning の優先順位に従う。
   - build メタデータは無視する。
   - プレリリースは正式版より小さいとみなす。したがって `0.161.0-alpha.1` は最低版未満、`0.164.0-alpha.1` は 0.164.0 未満として扱う。
4. **判定不能**: 次の場合は判定不能として対象外にする。上書き設定は設けない。
   - `userAgent` がない、または不正である
   - トークンが不正である
   - ソースビルドの `0.0.0` である
5. **判定のタイミング**: 接続ごとに 1 回、`initialize` 応答の受信後、`initialized` 通知の送信前に判定する。リモートサーバーは更新されることがあるため、再接続のたびに改めて判定する。
6. **拒否時の動作**: ローカルではプロセスを停止し、リモートでは WebSocket を閉じる。
   - 再試行しない失敗として通知し、自動回復を繰り返さない。
   - メッセージには、秘匿化した検出バージョン（判定できない場合は「不明」）、最低版 0.161.0、推奨版 0.164.0 を表示する。
   - ローカル接続では、CLI セットアップ文書と導入補助を案内する。リモート接続では、サーバーの更新を依頼する文言を表示する。拡張がサーバーを更新することはない。
   - CLI パスや接続先を変更できるよう、設定画面は引き続き開けるようにしておく。
7. **対象版より新しいバージョン**: 受け入れて 0.164 段階として扱う。`/status` に、検証済みのバージョンより新しいことを表示する。

### 機能段階

| 段階 | 条件 | 機能 |
| --- | --- | --- |
| 対象外 | 判定不能、または 0.161.0 未満 | 接続を拒否する |
| 基本 | 0.161.0 以上 | 既存機能、`/model` の引数、`/permissions` |
| 0.163 | 0.163.0 以上 | ローカルの MXC 無効化、experimental 交渉時の既読状態 |
| 0.164 | 0.164.0 以上 | プリセット、3 章の新しい挙動すべて、診断 ZIP の保存 |

段階は Worker が算出し、接続状態とともに Extension へ渡す。UI は、上位の段階が必要な機能を失敗させず、非表示にするか理由を表示する。

フィールドの欠落や未知の列挙値の許容は、すべての段階に適用する。たとえばプラン値 `sci`／`sci_plus` を受け取っても、アカウント表示や使用量表示を壊さない。

## 2. 入力操作と CLI 共通プリセット

### `/model`

構文は `/model [model] [--reasoning <level>] [--speed <tier>]` とする。`turn/start` のパラメーターを変えるだけなので、対応するすべての段階で使える。

引数の解析は CLI 0.164.0 のスラッシュコマンド解析に合わせる。こうすることで、どちらのクライアントで作ったプリセットも同じように動く。

- **トークン分割**: シェル形式で分割する。空白で区切り、一重引用符・二重引用符でまとめる。引用符が閉じていない場合はエラーにする。
- **値付きフラグ**: `--flag=value` と `--flag value` の両方を受け付ける。
  - 空白区切りの場合、次のトークンが `--` で始まらないときだけ値として採る。
  - 空の `--flag=` は次のトークンを値として採る。
  - 値がない場合はエラーにする。
- **エラーにするもの**: 同じフラグの重複（値が同じでも）、未知の `--name`。単独の `--` 以降はオプションとして解析しない。
- **位置引数**: モデル名の 1 つだけ受け付ける。

値の解決は次のとおり。

- **モデル**: 省略時は現在のモデルを使う。指定する場合は、現在のカタログにあり、ピッカーに表示されるモデルでなければならない。
- **推論強度**:
  - 推論強度もモデルも省略した場合は、現在の推論強度を維持する（なければモデルの既定値）。
  - モデルだけを指定した場合は、変更先モデルの既定値を使う。
  - 推論強度を指定する場合は、そのモデルが対応する値でなければならない。対応値の一覧を持たないモデルは既定値だけを受け付ける。
- **速度**:
  - `standard` は通常速度の明示指定とし、`default` として送る。`default` は CLI が「サービス階層なし」を表す要求値で、対応するすべてのバージョンで使える。
  - `flex` は `flex` として送る。
  - それ以外の値は、カタログの tier の ID、または名前（大文字小文字を区別しない）で照合する。利用できない値はエラーとし、利用可能な値の一覧を示す。
  - 省略した場合、変更後のモデルが現在の有効な tier に対応していれば維持し、対応していなければ通常速度に戻して通知する。CLI は省略時に tier を送らないので、これは意図的な差異である。
- **適用**: 全体を検証してから適用する。エラー時は何も変更しない。次の `turn/start` から反映し、実行中のターンには適用しない。`/fast` と `/reasoning` は引き続き使える。

### `/permissions`

既存の解決処理（組み込みモードの ID・表示名と、`permissionProfile/list` のプロファイル ID）と Full Access 確認をそのまま使う。権限の確認中は、送信待ちキューを進めない。プリセットから `/permissions` を実行した場合も、同じ確認を経る。

### プリセット

プリセットは 0.164 段階でだけ使える。それより古い接続では、コマンドとボタンで 0.164.0 以上が必要であることを案内する。

- **画面**: `/presets` と入力欄付近のボタンからパネルを開く。
  - 1～9、0 の順に 10 スロットを並べる。
  - 各スロットには、ラベル（ない場合は入力の 1 行目）、定義元のレイヤー、編集・削除の可否を表示する。
  - プリセットの文字列はサーバー由来なので、`SafeMarkdownService` を通してから表示する。
- **保存先**: 接続先サーバーの `tui.presets.<digit>` に `{input, label}` を保存する。リモート接続ではリモート側のユーザー設定を使い、ローカルの設定とは混ぜない。
- **検証**: CLI の `QuickDial::validate` と同じく、次の入力を拒否する。
  - 前後の空白を除くと空になる入力
  - 前方の空白を除いた先頭が `!` の入力
  - UTF-8 で 8,000 バイトを超える入力

  入力の改行と空白はそのまま保持する。ラベルは前後の空白を除き、未指定の場合は空文字を明示的に書き込む。空文字は下位レイヤーのラベルを打ち消す。
- **読み取り**: `config/read` を `includeLayers=true` と `cwd`（ワークスペースルートのサーバー側パス）を指定して呼ぶ。
  - スロットの値は、上位のレイヤーから順に `layers[].config.tui.presets` を読む。有効値の `config` は使わない（そのスキーマには `tui` キーがない）。
  - スロットの有効値は、そのスロットを定義する最上位レイヤーの値とする。
  - 書き込みに使うため、ユーザーレイヤーの `version` を保持しておく。
- **編集・削除の規則**:
  - 編集できるのは、どのレイヤーも定義していないスロットか、最上位の定義元がユーザーレイヤーのスロットだけとする。
  - 削除できるのは、ユーザー以外のどのレイヤーにも定義されていないスロットだけとする。こうすることで、削除によって隠れていた値が復活することはない。
  - サーバーの書き込み時の上書き検査は `cwd` を考慮しないため、現在のワークスペースについてクライアントがこの規則を適用する。プロジェクトレイヤーによる遮蔽は、ワークスペースごとに異なりうる。
- **書き込み**: `config/batchWrite` に、キーパス `tui.presets.<digit>`、`mergeStrategy` は `replace` の編集を 1 件だけ送る。値は `{input, label}`、削除の場合は `null` とする。
  - `expectedVersion` にはユーザーレイヤーのバージョンを指定する。ユーザーレイヤーがない場合は省略する。
  - Worker はこのキーパス以外への書き込みを許可しない。
  - バージョンが競合した場合は、編集内容を保持したまま再読み込みし、競合を表示する。自動では再送しない。
  - 成功した後も再読み込みする。その他のエラーは秘匿化して表示する。
  - 置換と削除は確認を経てから行う。
- **制約**: CLI の TUI はバージョンを検査せずに設定ファイルへ直接書き込み、プリセットをメモリ上に保持する。このため、CLI 側の同時編集は次の読み取りまで検出できない。また、実行中の CLI には、設定を再読み込みするまで拡張側の変更が反映されないことがある。
- **呼び出し**: スロットを選ぶと、その入力を入力欄に展開するだけで、送信はしない。下書きがある場合は置換を確認し、キャンセルすれば下書きを残す。送信はユーザーの通常の送信操作で行う。CLI はキューに入れて実行するので、これは意図的な差異である。
- **未対応コマンド**: `/title` や `/statusline` などの CLI 固有コマンドも保持・編集できる。送信時は既存の未対応コマンド処理で案内し、通常のプロンプトに変換することはしない。
- **再取得**: パネルを開いたときと、明示的に更新したときに再取得する。ポーリングはしない。結果は所有者と接続世代で照合する。

## 3. 状態・画像・MCP・診断・compaction

この章の新しい挙動は、すべて 0.164 段階でだけ有効にする。それより古い接続では現在の挙動を維持する。ただし、「すべての段階」と明記した項目は例外とする。

### 再開時のスレッド設定

0.164 段階では、`thread/resume` 応答の `model`、`reasoningEffort`、`serviceTier` を、会話と入力設定にまとめて反映する。

- `serviceTier` が null の場合は通常速度とし、以前の tier を解除する。
- `reasoningEffort` が null の場合はモデルの既定値とする。
- 以前の値を残さない。
- 反映の前に、所有者・接続世代・選択世代を検証する。

それより古いサーバーは、保存済みのスレッド設定ではなく全体の既定値を返す。このため古い接続では、従来どおり空でない値だけを反映する。

### アカウント変更

アカウント変更時の動作は ADR-013 に従う。所有者を置き換え、新しい所有者の接続処理の中で `model/list` を読み込む。

- 永続化しているモデル・推論強度・速度の選択は、新しいカタログに存在すれば維持する。存在しなければ新しいカタログの既定値に変更し、そのことを通知する。
- 前の所有者に対する遅延応答は破棄する。

制約: 次の 2 つのケースはクライアントから検出できない。そのため、カタログが新しいアカウントのものであるとは断定しない。

- 0.164.0 より古いサーバーは、プロセス内でアカウントが変わった後も、前のアカウントのカタログを保持し続けることがある。
- 0.164.0 は、カタログの更新に失敗すると前のプロバイダーカタログを保持する。

### 生成画像

- 0.164 段階では `fileId`、`result`、任意の `savedPath`、`inputImages`、`failure` を認識する。`fileId` と `result` が両方ある場合は、`fileId` を参照として使う。移行期に書かれた履歴に対する上流の扱いと同じである。
- 既存のパス検証を通る `savedPath` は、既存のプレビュー経路で表示する。
- インラインの `result` は標準の Base64 または data URI として扱う。デコードの前にサイズを制限し、PNG／JPEG の実体であることを検証する。
- `fileId` は attachment-store の内部 ID で、公開 RPC では解決できない。`thread/attachment/list` の ID とは同一視しない。
  - 参照しかない場合は「参照はあるが、この接続ではプレビューできない」と理由を表示する。
  - URL を組み立てたり、存在しない API を呼んだりしない。
- `inputImages` は生成元の情報として表示するだけで、そのパスを自動で読み込んだり再添付したりしない。
- 表示状態は `status` と `failure` から決める。処理中や失敗を、生成完了として表示しない。通知と履歴の再生には同じ処理を適用する。

### MCP

- 既存の `mcpServer/oauth/login`、認証 URL の検証、`loginId` による完了照合を維持する。エンタープライズ向け資格情報の選択・保管・交換は CLI に任せる。
- 0.164 段階では、次の 3 つを分けて表示する。
  - 認証状態（`authStatus`）
  - 実行時の接続状態（`runtimeStatus`）。値が欠落しているか未知の場合は「不明」とする。
  - ツール取得の結果（ツール数、または `toolsError`）
- 表示の規則は次のとおり。
  - `authStatus` が資格情報の種類を示していても、`runtimeStatus` が `authenticationRequired` なら再認証が必要と表示する。
  - ツール数がゼロであることだけを根拠に、故障や未認証とは判断しない。
- `toolsError` は長さを制限し、`ISecretRedactor` と `SafeMarkdownService` を通して表示する。不透明な `toolListMeta` は、Worker 契約にも UI にもログにも流さない。
- 認証の完了後やアカウント変更後は状態を再取得し、以前の所有者に対する結果は破棄する。

### 診断 ZIP

- 「診断 ZIP を保存」を、フィードバック送信とは別の操作として追加する。0.164 段階でだけ使える。
- Worker 契約 v26 に `SaveFeedbackRequest`／`SaveFeedbackResult` と、`feedback/save` を呼ぶ Worker メソッドを追加する。
  - classification には既存の `visual-studio` を使う。
  - 選択中の会話の `threadId` を指定する。
  - 追加のログファイルは指定しない。
- ログの同梱は既定でオフにする。オフの場合、上流はレポートと診断テキストだけを書き込み、rollout やログファイルは含めない。保存の前に、保存内容と保存先ホストを確認画面で示す。
- ローカル接続では保存先の選択画面を使う。サーバーは既存ファイルを上書きしないため、既に存在するパスは RPC を呼ぶ前に拒否し、別の名前を選んでもらう。
- リモート接続では、サーバー上の絶対パスを入力してもらう。
  - 結果はサーバー側のパスであることを明示し、ローカルファイルとして開かない。
  - 既存パスなどのサーバーエラーは、秘匿化して表示する。
- 切断やタイムアウトは「結果を確認できなかった」として扱い、自動では再送しない。

### compaction の失敗と圧縮済み履歴

- **すべての段階**:
  - compaction の完了とみなすのは、`thread/compacted` を受信したとき、または `contextCompaction` 項目が完了したときだけとする。
  - compaction 中の RPC エラー、エラー通知、ターンの失敗は「compaction に失敗した」と表示する。拡張は compaction の目印を追加せず、再試行もしない。サーバー側の履歴が変わるかどうかは、次に示すとおり段階によって異なる。
  - 表示する履歴は常にサーバーから取得する。拡張側で要約項目を合成したり隠したりはしない。
- **0.164 段階**: 上流は、失敗した compaction の部分的な要約を履歴に残さなくなったため、履歴は変更されない。また、圧縮済みの履歴を再開できるようになった。クライアント側に追加の処理は不要である。
- **それより古い段階**:
  - 失敗した compaction の部分的な要約がサーバー履歴に残ることがある。これは返されたとおりに表示する。
  - 圧縮済みの履歴を再開できない場合がある。その場合は秘匿化したエラーを表示し、CLI 0.164.0 では圧縮済み履歴を再開できることを案内する。履歴の行は残し、自動では再試行しない。

## 4. Worker 契約

Worker 契約を v25 から v26 に更新し、次の型付き DTO を追加する。

- **接続状態**: 検出したバージョンと機能段階。回復失敗の種別に「サーバーバージョン対象外」を追加する。
- **プリセット**: 一覧・保存・削除。各スロットの入力、ラベル、定義元レイヤー、編集・削除の可否、ユーザーレイヤーのバージョン、競合の結果を持つ。
- **診断 ZIP**: 保存の要求と結果。
- **MCP**: 実行時状態、ツール数、長さを制限した `toolsError`。
- **生成画像**: 参照しかない状態と、その理由。

新しい非同期の結果は、すべて所有者・接続世代・選択世代で照合してから適用する。

## 5. 検証

- **契約**: 4 バージョン × 2 surface の検証、`minimumVersion` の検証、定数とマニフェストの一致。
- **バージョン判定**:
  - 拒否されることを確認する: 0.159.1、0.160.x、`0.161.0` のプレリリース、`0.0.0`、`userAgent` の欠落・不正。
  - 受け入れられることを確認する: 0.161.0、0.162.1、0.163.0、0.164.0、それより新しいバージョン。
  - 拒否後に自動回復が繰り返されないこと。
  - `0.164.0-alpha` での段階判定。
- **入力**:
  - `/model` の解析が CLI と一致すること（引用符、`=` 形式、空白区切り、空の値、重複、未知のフラグ、`--`、余分な引数）。
  - 一括適用、速度のフォールバック、`/permissions` の確認、確認中に送信待ちキューを進めないこと。
- **プリセット**:
  - 検証の境界（8,000 バイトと 8,001 バイトを含む）。
  - project／system／session レイヤーがある場合と、ユーザーレイヤーがない場合の、読み取りと編集・削除の規則。
  - 競合、下書きの保持、CLI が書いたスロットの読み込み、リモート側の分離、接続先の切り替え。
- **状態・画像・MCP**:
  - 0.164 と旧版での再開（tier と推論強度が null の場合を含む）。
  - アカウント変更中の遅延応答。
  - 画像の各形式: `fileId` のみ、`result` のみ、両方、`savedPath`、data URI、破損・過大な入力、失敗・処理中、履歴の再生。
  - MCP 状態の組み合わせと再認証。
- **診断**: ローカル・リモートでの保存、既存パスの拒否、ログ同梱の選択、結果未確認、段階による制限。
- **compaction**:
  - Fake App Server で、compaction の失敗と、旧版での再開エラーのシナリオを確認する。
  - 実際の 0.164.0 CLI で、compaction 後に再起動して再開できることを確認する。
  - 実 CLI では compaction の失敗を安定して再現できないため、失敗系は Fake のシナリオで確認し、実機で試した結果を記録する。
- **実機**: Windows 上での 0.164.0 による MXC 起動と、0.161.0 での回帰接続。
- **品質**:
  - Core／UI／Fake テスト、Debug／Release の警告ゼロビルド、VSIX の検査。
  - Experimental Instance で、各テーマ、狭い幅、日本語、キーボードのみの操作、スクリーンリーダー出力を確認し、スクリーンショットで判定する。

## 6. 対象外

- .NET・NuGet は変更しない。
- 次の機能は移植しない: Kitty／Sixel プレビュー、Bedrock の TUI ウィザード、experimental の `thread/sample`、WebSocket 圧縮。
- CLI 内部の Windows プロキシ認証の修正は、拡張自身の .NET WebSocket がプロキシに対応したことの根拠にはしない。
