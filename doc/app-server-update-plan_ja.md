# Codex App Server 更新とリモート接続の計画

この計画では、ローカル stdio を既定のまま維持しながら、拡張機能の Codex App Server 連携を更新する。起動済みリモートサーバーへの明示的な安全な WebSocket 接続、再接続と履歴復元、要求の厳密な振り分け、質問・承認処理、日常利用に必要な app-server 機能を追加する。

## 対象範囲と不変条件

- ローカル stdio が既定であり、所有する子プロセスを管理する。リモート接続はクライアント接続だけを管理し、サーバー再起動ではなく再接続を提供する。
- リモート転送は `wss` を受け付け、平文 `ws` は loopback に限定する。認証はトークンファイルを使い、トークン本文を設定・ログ・Remote UI に保存しない。証明書検証を無効化する機能は設けない。
- ローカル側とサーバー側のルートを別のパス型で表す。作業ディレクトリ、IDE コンテキスト、添付、画像、変更リンクにはパス要素単位の対応付けを使い、ファイル同期は対象外とする。
- 状態とキャッシュは接続先、アカウント、作業ルートごとに分離する。リモートの sandbox 制約はリモートサーバーが実施する。
- 未知のサーバー要求を承認処理へ流さない。秘密を含む要求は安全な専用入力経路がない限り拒否する。

## 実装フェーズ

1. **プロトコル契約と転送基盤**: CLI 0.154.0 を契約検証基準に固定し、標準・実験的スキーマを分離生成する。スキーマキャッシュの版情報を管理し、initialize の OS 情報を保持する。capability、読み取り専用 probe、`-32601` で機能を判定し、要求の完全一致振り分けと接続世代単位の thread/turn 状態を追加する。
2. **リモート接続**: Worker 内で stdio と WebSocket を切り替え、接続先と認証を検証する。接続・再接続を直列化し、読み取り専用 RPC には jitter 付き指数バックオフを適用する。health と RPC 利用可否を区別する。
3. **パスと状態の分離**: ローカル／サーバーのルート対応付けを導入し、パスを含む入力とリンクに一貫して適用する。対応できない添付は送信前に拒否し、スキル、モデル、使用量、承認、選択中会話の状態を分離する。
4. **再接続と履歴復元**: 下書きをメモリに保持し、再接続後に再初期化する。対応する場合は履歴をページ取得し、通知を thread・turn・item ID で統合する。配送状態が不明な操作は自動再送せず、履歴閲覧と再試行を提供する。
5. **質問・承認・MCP 対話**: Worker 契約を v15 から更新し、質問、権限要求、MCP 入力を別型で扱う。二重回答、キャンセル、切断、解決通知を処理し、部分的な権限許可、MCP フォーム、ブラウザー認証を秘密情報を漏らさず提供する。
6. **日常利用機能**: plan の差分と確定内容、thread・設定・モデル状態、型付き MCP・成果物を表示する。モデルカタログに基づく入力 modality と推論量を扱い、承認ポリシー下で明示実行する `thread/shellCommand` と、コマンド／RPC 別 timeout を追加する。Windows の sandbox 初期設定状態も表示する。
7. **統合検証とリリース準備**: 契約差分、通知競合、転送障害、パス境界、権限対話、Light/Dark/High Contrast の UI アクセシビリティを検証する。対象テスト、全体テスト、Debug/Release ビルド、VSIX 検査、Experimental Instance のスクリーンショット確認を行う。

## 完了条件

- 対応メッセージは厳密なメソッド・型契約で処理し、未知の要求はプロトコルに沿って拒否する。
- 古い接続の応答・通知が完了済み turn や現在の接続状態を復活・変更しない。
- 安全なリモート接続、ルート対応付け、キャッシュ分離、再接続、ページ単位の履歴復元が動作し、不明な変更操作を再送しない。
- 部分承認、非同期質問、解決通知競合、対応フォーム、秘密入力を安全に扱う。
- shell 実行は明示的・制限付き・接続先表示付きで、既存の承認ポリシーに従う。
- Core/UI テスト、警告ゼロの Release ビルド、VSIX 検査、Experimental Instance の表示・アクセシビリティ確認が成功する。
