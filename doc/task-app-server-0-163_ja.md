## レビュー指摘への対応(競合・UI のロック)

- [x] 更新が終わった時点で既読操作の表示状態を通知し直すようにしました。成功、競合、再取得のいずれの後も、ボタンが非表示のまま残りません。
- [x] 一覧取得の排他を owner ごとにしました。
  - 前の owner の遅い要求が、新しい owner の最初のページを止めなくなりました。
  - 新しい owner に切り替わった後で前の owner の回復同期が終わっても、新しい owner の一覧を「同期できなかった」状態にしなくなりました。
  - 失敗メッセージは、現在の owner の要求に対してだけ表示します。
- [x] 表示中と同じ状態を持つ通知(自分の更新が確定したことを知らせる通知を含む)を、並行した変更として扱わないようにしました。
- [x] 会話を選択しても直前の未読表示を保持します。履歴の読み込みに失敗しても未読表示は消えません。
- [x] OOP の環境では OnUiAsync が呼び出し元のスレッドでそのまま実行されます。そのため、行と既読状態の管理情報を1つのロックで保護しました。更新中を示すトークンは ViewModel の寿命を通じて一意なので、前の owner の要求が新しい更新の処理中状態を解除することはありません。
- [x] ThreadRows は Threads と同じ順序を位置ごとに保ち、追加と削除だけを差分で反映します。読み込み済みのページから外れた会話を選択していても、余分な行は表示しません。Threads は Remote UI に送らなくなりました。
- [x] thread/readState/update が timeout または切断で終わった場合は、OutcomeUnknown(結果未確認)として返します。クライアントは現在の状態を1回だけ読み直し、更新は再送しません。
- [x] 0.163 未満の CLI で MXC の使用禁止を拒否したときは、接続コンテキストを破棄し、検出した版とメタデータを消去します。
