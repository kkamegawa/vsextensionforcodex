## Changes

- Local-start proof confirmed by the StartTurn response is keyed by owner, connection generation, thread and turn, and is not lost on temporary empty or different-turn status notifications or while waiting on a question. Composer sends, question-answer follow-ups and direct `/plan <prompt>` starts share the bookkeeping. The notification ordering reported inside the IDE remains unconfirmed.
- Completion of the matching turn retires its proof, and a completion that arrives before the start response prevents the proof. Owner or connection changes, Disconnected and Degraded clear both the proof and the pending acknowledgements. Every record is bounded.
- Ordinary interruption is allowed only for the exact turn with local-start proof that is currently Busy or WaitingForApproval on the selected, joined thread. Turns started by other clients remain ineligible. Existing Goal Stop behavior is retained.
- When the start response is lost after dispatch (delivery outcome unknown), the `turn/started` notification on the same owner, connection generation and thread identifies the turn: one observed while the request was pending, otherwise the next one. A newer local start on the same thread supersedes the lost start, so later turns are never attributed to it.
- Remote UI is notified when eligibility changes. The diagnostic records only the state and eligibility booleans when they change, with no prompt, answer, path or raw ID.
